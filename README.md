# RouteManager（路由管理）

## 一分鐘摘要

- **是什麼**：macOS 原生選單列＋主視窗 App，用圖形介面看 IPv4 路由表、加／刪臨時靜態路由、把常用路由存起來一鍵套用。取代手打 `netstat -rn`、`sudo route add`。
- **怎麼編譯怎麼開**：在此資料夾跑 `./build.sh`，產出 `build/RouteManager.app`，雙擊開啟。選單列會出現分岔圖示。測試：`swift test`。
- **分享給別人**：跑 `./make-dmg.sh`，產出 `build/RouteManager-<版本>.dmg`（通用版，Apple 晶片與 Intel 都能跑，需 macOS 14 以上）。dmg 內附「先讀我.txt」教對方怎麼安裝。因為沒有 Apple 開發者簽章，對方第一次開要按右鍵→「打開」。
- **他要做的事**：第一次實際套用／刪除路由時，系統會跳授權視窗（這版沒有實測過這一步，請親手試一次）。
- **風險與限制**：路由是臨時的，重開機消失，靠「已存路由」重新套用。改路由需管理員授權，每次操作前會先顯示完整指令讓你確認；做完會重讀路由表核對，沒成功的會列出來。系統自己建的路由（介面直連網段、預設閘道）不可刪。

## 功能

- **選單列**：顯示預設閘道與介面；已存路由逐筆顯示 ● 生效／○ 未生效，可套用或移除；全部套用／移除；開啟主視窗；重新整理；結束。
- **目前路由表**：目的地、閘道、旗標、介面；可搜尋；預設隱藏 link-local、multicast、廣播、主機快取（W／L 旗標）雜訊，可打開開關全顯示；選取有 S 旗標的靜態路由可刪除。
- **已存路由**：新增、編輯、刪除；欄位為名稱、目的網段、閘道 IP 或介面名、備註；每筆有套用／移除與生效狀態；全部套用一次只問一次授權。
- 啟動時會自動開主視窗（避免選單列圖示被收起來時以為沒開）。關閉主視窗後 App 留在選單列，Dock 圖示隱藏；從選單列「開啟主視窗」會再顯示。
- 選單列狀態每 15 秒自動重新整理一次（netstat 很便宜）。套用／移除進行中，按鈕會停用，避免連按跳兩次授權。

## 安全設計

- 進到特權 shell 的值，一律先過 `RouteCore` 的嚴格驗證，並由解析後的數字重建字串（不是直接用輸入）：
  - IPv4 逐段 0–255、不接受前導 0；前綴 0–32；CIDR 主機位元必須為 0，否則拒絕並提示正確網段。
  - 介面名只接受 `^[a-z]+[0-9]+$`，且必須存在於當下 `ifconfig` 列出的介面。
  - 名稱、備註只存 JSON，不會進 shell。
- 指令只有寫死絕對路徑的樣式。新增：`/sbin/route -n add -net <CIDR> <閘道>` 或 `... -interface <介面>`；刪除：`/sbin/route -n delete -net <CIDR>` 後面接 `<閘道>` 或 `-interface <介面>`（二選一）。/32 一律把 `-net <CIDR>` 換成 `-host <IP>`。送出前再做一次字元白名單檢查。
- **帶 I 旗標的 scoped（介面限定）路由不處理**：旗標含 `I` 的列不可刪；只要同目的地有任何一列帶 I，表格刪除與已存路由移除都不送指令，提示「此目的地有介面限定（scoped）路由，請改用終端機處理」。
- 拒絕新增或刪除 default（0.0.0.0/0）與任何和 127/8 重疊的網段（連 0.0.0.0/1 也會被擋），UI 上這些列不可刪。
- 套用前跳確認對話框，列出將執行的完整指令。指令失敗會顯示 route 的錯誤訊息；取消授權視窗不算錯誤，靜默返回。

## 系統路由、/32、事後核對

- **系統路由不可刪**：旗標分不出系統建的與手動加的（都是 S），所以改看 `ifconfig`：目的地等於某介面直連網段、介面本機位址的 /32、或目前預設閘道 IP 的 /32，一律視為系統路由。表格不可刪；已存路由若對上，狀態顯示「系統路由」，套用與移除都停用，「全部套用／全部移除」會略過。point-to-point（`inet A --> B`）的位址不當成直連網段。
- **/32 用 `-host`**：新增與刪除 /32 時組成 `route -n add -host <IP> ...`、`route -n delete -host <IP>`，其餘用 `-net <CIDR>`。
- **事後核對**：不只看 exit code。執行完會重讀路由表，檢查該新增的有沒有出現、該刪的有沒有消失；沒成功的列出來，連同指令輸出一起顯示。
- **全部套用會略過無效項**：欄位無效、介面當下不存在、與系統路由衝突的會被略過，其餘照常套用，結束後說明略過了哪幾筆與原因。
- **出錯時保守擋住**：`netstat` 或 `ifconfig` 執行失敗、輸出為空、或解析不到任何帶 inet 的介面時，視為「讀不到介面資訊」，主視窗與選單列會顯示「讀不到介面資訊，暫停刪除功能」，表格刪除、已存路由的「移除」與「全部移除」全部停用；套用不受影響。
- **第二道系統路由規則**：不依賴 netmask。閘道是 `link#N`、且目的網段包含該介面自己任一 inet 位址的路由，也視為系統路由（涵蓋 ifconfig 缺 netmask 欄位的情況）。
- **按下當下重讀**：刪除、移除、全部移除都會先重新讀 `netstat` 與 `ifconfig`，再判斷與組指令，不用 15 秒前的快取。
- **表格刪除 link#N 的列**：指令也帶 `-interface <介面>`（須存在於系統），事後核對一併比對介面。
- **可信判斷不算 loopback**：至少要有一個非 loopback（名稱不以 `lo` 開頭）的介面帶 inet，資料才算可信；只剩 lo0 的 127.0.0.1 一律視為讀不到介面資訊。
- **以介面為目標的已存路由**：移除指令會帶介面，例如 `route -n delete -net 10.20.60.0/24 -interface utun9`（/32 為 `-host <IP> -interface <介面>`）。若路由表中同目的地有多條，只在恰有一條介面相符時才送出；否則不送，並提示到「目前路由表」頁手動處理。
- **已存路由缺 id**：讀到沒有 id 的項目會補上並回存一次，之後固定。
- 失敗標記是 `ROUTEMGR_FAILED`（不含萬用字元）。表格選取用穩定 id（目的地＋閘道＋介面＋旗標），重新整理後不存在的選取會清掉；刪除送出的指令與確認框顯示的是同一份值。
- routes.json 缺欄位（如沒有 note）不會被當成壞檔。

## 檔案

- 已存路由：`~/Library/Application Support/RouteManager/routes.json`（原子寫入；若檔案壞掉，會改名保留為 `routes.json.corrupt-時間戳` 並以空清單啟動，不會刪）。
- 結構：`Sources/RouteCore`（解析、驗證、組指令、儲存；有單元測試）、`Sources/RouteManager`（SwiftUI 介面與授權執行）、`Tests/RouteCoreTests`（含本機實際 `netstat -rn -f inet` 輸出當 fixture）。
- App 圖示：`Assets/AppIcon.icns`，由 `Assets/make-icon.swift` 畫出（藍底、三節點路徑加箭頭）。`build.sh` 會把它放進 .app。要改圖就改腳本後執行：`swift Assets/make-icon.swift /tmp/icon_1024.png`，再用 `sips` 縮成 16～1024 各尺寸放進 `AppIcon.iconset/`，最後用 `iconutil -c icns` 產生新的 .icns 蓋掉舊的。

## 未做

- 沒有做永久路由（不碰 `networksetup -setadditionalroutes`）。
- 只管 IPv4。不處理 IPv6、不處理 scoped（`-ifscope`）路由。
- 刪除表格中的路由時，只依「目的網段（＋閘道為 IP 時帶閘道）」下 `route delete`；介面路由（閘道為 link#N）用不帶閘道的形式。
- 排除系統路由後，帶 S 旗標的列仍可刪，包含 VPN 軟體自己建的路由（例如經 utun 的網段）；刪之前會確認，請自行判斷。
- 程式沒有 Apple 開發者簽章（ad-hoc）。若被 Gatekeeper 擋，跑 `xattr -cr build/RouteManager.app`。
- `.build/` 與 `build/` 是編譯產物，若此資料夾有被同步，建議在同步工具排除。
